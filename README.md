# fb2read

Читалка книг FB2 и EPUB для терминала: Linux, macOS, Windows и Android.

## Установка

**Linux и macOS.** Ставит готовый бинарник в `~/.local/bin`; ничего заранее
устанавливать не нужно:

```bash
curl -fsSL https://w2713.github.io/fb2read/install.sh | sh
```

**Windows.** Кладёт программу в папку пользователя и прописывает её в `PATH`:

```powershell
irm https://w2713.github.io/fb2read/install.ps1 | iex
```

**Android (Termux) и все, у кого уже есть Node:**

```bash
npm install -g fb2read
```

Установщик сам определяет систему и процессор, сверяет контрольную сумму
скачанного и отказывается ставить, если она не сошлась. Куда положить
программу и какую версию взять, задаётся переменными `FB2READ_INSTALL_DIR`
и `FB2READ_VERSION`.

Готовые сборки лежат в [релизах](https://github.com/w2713/fb2read/releases):
Linux (x64 и arm64, glibc и musl), macOS (Intel и Apple Silicon), Windows
(x64 и arm64). Под Android отдельной сборки нет — там работает вариант с npm.

Собрать самому:

```bash
pnpm install && pnpm build
./scripts/build-binaries.sh          # бинарники под все системы
```

## Запуск

```bash
fb2read book.fb2            # читать книгу
fb2read book.epub           # EPUB работает так же
fb2read book.fb2.zip -2     # книжный разворот из двух страниц
fb2read ~/books             # библиотека: список книг в каталоге
fb2read                     # список недавних книг с прогрессом

fb2read book.fb2 --dump | less -R   # текст в конвейер
fb2read book.fb2 --toc              # оглавление
fb2read book.fb2 --info             # сведения о книге и внесённые правки
```

Полезные ключи: `-w 72` — ширина колонки, `-s 2` — межстрочный интервал,
`--theme night` — цветовая тема, `-2` / `-1` — разворот или одна колонка,
`--images off` — без картинок, `--no-mouse` — не захватывать мышь,
`--justify` — ровный правый край, `--hyphens` — переносы по слогам,
`--from-start` — не восстанавливать позицию.

## Клавиши

| Клавиши | Действие |
|---|---|
| `j` `k` `↓` `↑` | строка вниз / вверх |
| `Space` `PgDn` `→` `f` / `b` `PgUp` `←` | страница вперёд / назад |
| `d` `u` | полстраницы |
| `g` `G` `Home` `End` | начало / конец книги |
| `[` `]` | предыдущая / следующая глава |
| `t` `o` | оглавление |
| `/` `n` `N` | поиск и переходы по совпадениям |
| `l` | список всех совпадений с контекстом |
| `M` | поставить или снять закладку |
| `'` `"` | закладки: переход, удаление, экспорт |
| `Enter` `Backspace` | перейти к сноске / вернуться |
| `1` `2` `v` | одна колонка / книжный разворот |
| `s` | межстрочный интервал (1 / 2 / 3) |
| `J` | выключка по формату: ровный правый край |
| `H` | переносить слова по слогам |
| `+` `=` `-` | ширина колонки |
| `c` | тема: авто → ночь → сепия → день |
| `p` | показать иллюстрацию с экрана |
| `i` | сведения о книге |
| `S` | синхронизировать эту книгу с сервером |
| `Ctrl+L` | перерисовать экран |
| `m` | отпустить мышь и вернуть захват |
| колесо, клик | листать; клик по сноске или картинке; правая кнопка — назад |
| `?` `h` | справка |
| `q` `Q` | выход, позиция сохраняется |

Размер шрифта задаётся терминалом (`Ctrl` + `+` в большинстве эмуляторов,
`setfont` в консоли Linux); текст сам переливается под новый размер окна.

## Что умеет разбор

* `.fb2`, `.fb2.zip`, `.fbz`, `.epub`; кодировка определяется даже без объявления;
* EPUB 2 и 3: порядок чтения берётся из spine, оглавление из `nav` или NCX,
  ссылки на сноски работают между файлами книги, заголовки, списки, цитаты
  и таблицы раскладываются так же, как в FB2;
* заголовки, вложенные разделы, эпиграфы, цитаты, стихи, таблицы, сноски;
* курсив и полужирный доходят до экрана, ширина символов считается честно
  (иероглифы — два знакоместа, эмодзи — два, диакритика — ноль);
* починка типичных поломок: неэкранированный `&`, `&nbsp;` и прочие HTML-сущности,
  мусор до и после документа, управляющие байты. Все правки видны в `--info`;
* `<binary>` вырезаются до разбора, поэтому книги с картинками открываются
  вдвое быстрее и не занимают лишнюю память: запоминаются только границы
  вложения в файле, а данные читаются в момент показа.

## Иллюстрации

Клавиша `p` показывает картинку, попавшую на экран (если их несколько —
предлагает выбрать). Читалка отдаёт экран целиком, рисует изображение и по
любой клавише возвращается к тексту.

| Терминал | Как рисуется |
|---|---|
| kitty | графический протокол kitty (PNG отправляется как есть) |
| iTerm2, WezTerm | OSC 1337, любой формат |
| любой с `chafa` | внешний конвертер, цветные символы |
| любой с `img2sixel` | sixel |
| остальные | сообщение с подсказкой поставить `chafa` |

Способ выбирается сам, но его можно задать: `--images kitty`, `--images chafa`,
`--images off`. В настройках он не сохраняется — зависит от того, где книгу
открыли.

Позиция чтения, тема, интервал и режим колонок хранятся в
`$XDG_DATA_HOME/fb2read/positions.json` (по умолчанию `~/.local/share`).

## Библиотека

Без аргумента читалка показывает недавние книги с процентом чтения, с
каталогом — все книги в нём; автора и название достаёт без полного разбора,
поэтому список строится быстро. Дочитанные книги приглушены. Список
листается `j` `k`, `PgUp` `PgDn`, колесом мыши, `g` `G`; `Enter` или клик
открывают книгу, `q` выходит. После чтения возвращаешься к списку с
обновлённым прогрессом. Если вывод перенаправлен в файл или конвейер,
список печатается текстом и читалка не занимает экран.

## Поиск

`/` ищет по всей книге сразу: показывает, какое совпадение по счёту из
скольких, подсвечивает все попадания на экране и переходит по ним клавишами
`n` и `N` с переходом через конец. `l` открывает список найденного — каждая
строка с процентом по книге и кусочком текста вокруг совпадения, выбор
переносит туда. Регистр не важен, ё и е считаются одной буквой. Пустой
запрос сбрасывает поиск и подсветку.

## Закладки

`M` ставит закладку на текущее место и снимает её повторным нажатием;
отмеченные абзацы помечаются полоской на левом поле. `'` открывает список
закладок с процентом по книге и первой строкой текста: `Enter` переносит
туда, `d` удаляет, `e` выгружает всё в markdown — заголовок книги, автор и
по несколько абзацев цитаты под каждой закладкой. Закладки хранятся рядом с
позицией чтения и переживают перезапуск.

## Мышь

Колесо листает текст, оглавление и список книг; клик по подчёркнутому
маркеру сноски открывает её, клик по метке иллюстрации показывает картинку,
правая кнопка возвращает из сноски. Пока мышь захвачена, терминал отдаёт
клики программе и обычное выделение текста не работает — в большинстве
терминалов помогает Shift, а иначе захват снимается клавишей `m` или ключом
`--no-mouse`. Используются SGR-репорты, поэтому клики приходят и в окнах
шире 223 колонок.

## Синхронизация

Книги и позицию чтения можно держать на своём сервере: начали на ноутбуке —
продолжили с того же места на другой машине. Сервер свой, не чужой; ничего,
кроме указанного вами адреса, читалка никуда не отправляет.

Настраивается разделом в конфиге:

```ini
[sync]
url = https://books.example.org
token = ...            либо переменная окружения FB2READ_SYNC_TOKEN
auto = yes             сливать позицию при открытии и выходе из книги
upload = yes           выгружать саму книгу, когда её открыли
```

`upload = yes` — то, что избавляет от ручной работы: книгу, открытую на
ноутбуке, вечером видно на телефоне, ничего для этого не набирая. Выгрузка идёт,
пока вы читаете, и чтению не мешает; книга, уже лежащая на сервере, второй раз
не отправляется. По умолчанию выключено намеренно: книги весят мегабайты, и
решать, сколько их держать на сервере, должны вы.

Команды:

| Команда | Что делает |
|---|---|
| `fb2read sync` | обменяться позициями и закладками, книги не трогая |
| `fb2read push ЧТО` | выгрузить книгу, каталог книг или `--all` — всю библиотеку |
| `fb2read pull ЧТО` | скачать книгу; `--all` — все |
| `fb2read remote` | показать, что лежит на сервере, с прогрессом |
| `fb2read forget ЧТО` | удалить книгу с сервера: она исчезнет на всех устройствах |

Скачанное кладётся в `~/Books/fb2read` (меняется переменной
`FB2READ_LIBRARY`). Книги, которых на этом устройстве нет, видны в списке
под знаком `☁` и скачиваются по `Enter`.

Размер текста меняется кнопками `А−` и `А+` в панели чтения: он запоминается и
относится только к книге — панель и полка от него не растут. Место при этом не
теряется: читалка держится не за номер абзаца, а за долю, на которой его
читают, и после перевёрстки возвращает читателя туда же.

Версия читалки написана на первом экране. С домашнего экрана адресной строки
нет, и узнать, доехало ли обновление до телефона, иначе неоткуда.

Книга, убранная с полки в браузере, обратно сама не приезжает: она остаётся
видна облаком — «есть на сервере, но не здесь» — и возвращается по касанию.
Убрать с устройства и удалить книгу совсем — разные вещи: первое освобождает
место на телефоне, второе отбирает книгу у всех устройств и потому спрашивает
согласия.

Книгу можно добавить в библиотеку прямо из списка: клавиша `a`, затем путь к
файлу или к каталогу с книгами. Указанное копируется в каталог библиотеки и
появляется в списке — книга, скачанная в «Загрузки», больше не требует ни
`cp`, ни выхода из читалки. Место и закладки при этом не сбрасываются: книга,
которую уже читали, останется на своей странице.

Прямо во время чтения синхронизировать книгу можно клавишей `S`: она
отправляет то место, где вы сейчас, и приносит закладки с других устройств —
они появляются сразу, не дожидаясь перезапуска. Что вышло, читалка говорит в
строке состояния; сервер не настроен или недоступен — скажет и это, а чтению
не помешает.

**Что синхронизируется.** Позиция, закладки и сами книги. Настройки — нет:
ширина колонки и тема зависят от терминала, а он на каждой машине свой.

**Как решаются расхождения.** Позиция — по времени: побеждает записанная
позже. Закладки объединяются, а снятая закладка запоминается снятой, иначе
она возвращалась бы с устройства, которое о снятии не знает. Если часы
устройства ушли больше чем на пять минут, сервер об этом предупредит: слияние
держится на времени, и по неверным часам оно наврёт.

**Читать это не мешает.** Нет сети, выключен сервер, не тот токен — книга
всё равно открывается; ожидание при открытии ограничено тремя секундами, а о
неудаче читалка говорит один раз и не мешает дальше.

Книга узнаётся по отпечатку содержимого, а не по имени файла, поэтому на
другом устройстве она найдётся под любым именем и в любом каталоге. Книги,
читанные до появления синхронизации, отпечатка не имеют — он появится, когда
вы их откроете; `fb2read sync` про такие скажет.

### Свой сервер

```bash
npm install -g fb2read-server

FB2READ_SERVER_TOKENS="я:$(openssl rand -hex 32)" \
FB2READ_SERVER_DIR=~/fb2read-data \
  fb2read-server
```

Либо готовым бинарником из релиза (`fb2read-server-linux-x64.tar.gz` и
такие же под arm64 и musl), либо в Docker:

```bash
docker build -f packages/server/Dockerfile -t fb2read-server .
docker run -d --name fb2read \
  -p 127.0.0.1:8787:8787 \
  -v ~/fb2read-data:/data \
  -e FB2READ_SERVER_TOKENS="я:ваш-токен" \
  fb2read-server
```

Настройки — переменными окружения:

| Переменная | Что задаёт |
|---|---|
| `FB2READ_SERVER_TOKENS` | токены `имя:токен` через запятую; без них сервер не запускается |
| `FB2READ_SERVER_DIR` | каталог с данными |
| `FB2READ_SERVER_PORT` | порт, по умолчанию 8787 |
| `FB2READ_SERVER_HOST` | адрес, по умолчанию только 127.0.0.1 |
| `FB2READ_SERVER_MAX_MB` | предел размера книги, по умолчанию 200 |

Несколько токенов — несколько человек, у каждого свой каталог и свои книги.
Токен должен состоять из латиницы: в заголовке HTTP другого не передать, и
сервер с кириллическим токеном не запустится, чтобы вы не гадали, почему всё
отвечает «нужен токен».

Данные лежат просто файлами — их можно скопировать, положить в архив и
посмотреть глазами:

```
<каталог>/<пользователь>/books/<отпечаток>.fb2
<каталог>/<пользователь>/state/<отпечаток>.json
<каталог>/<пользователь>/index.json
```

**Сертификаты сервер не выдаёт намеренно** — этим лучше занимается reverse
proxy. Пример на Caddy, которому достаточно двух строк:

```caddyfile
books.example.org {
    reverse_proxy 127.0.0.1:8787
}
```

Пускать сервер в интернет без TLS не стоит: токен уходит в заголовке, и по
открытому HTTP его увидит любой по дороге.

## Настройки

`fb2read --write-config` кладёт образец со всеми действиями и их клавишами по
умолчанию. Где именно — зависит от системы:

| Система | Настройки | Позиции и закладки |
|---|---|---|
| Linux, macOS | `~/.config/fb2read/config.ini` | `~/.local/share/fb2read/positions.json` |
| Windows | `%APPDATA%\fb2read\config.ini` | `%LOCALAPPDATA%\fb2read\positions.json` |

На Linux и macOS чтутся `XDG_CONFIG_HOME` и `XDG_DATA_HOME`, если заданы, —
там же лежит состояние эталонной версии на Python, так что обе читалки видят
одни и те же позиции. Книги, скачанные с сервера синхронизации, ложатся в
`~/Books/fb2read` (на Windows — в `Books\fb2read` в папке пользователя);
другое место задаётся переменной `FB2READ_LIBRARY`.

Образец выглядит так:

```ini
[reader]
# width = 80          ширина текстовой колонки
# spacing = 1         межстрочный интервал: 1, 2 или 3
# columns = 1         1 — одна колонка, 2 — книжный разворот
# theme = auto        auto, night, sepia, day
# images = auto       auto, kitty, iterm, chafa, sixel, off
# mouse = yes         захватывать ли мышь
# justify = no        выключка по формату: ровный правый край
# hyphens = no        переносить слова по слогам

[sync]
# url = https://books.example.org
# token = ...
# auto = yes
# upload = yes

[keys]
# next_chapter = ]
# prev_chapter = [
# quit = q, Q
```

Понимаются одиночные символы, имена `space`, `enter`, `backspace`, `tab`,
`esc`, `delete`, стрелки, `pgup`, `pgdn`, `home`, `end` и сочетания вида
`ctrl-l`. Справка по `?` строится из действующей раскладки, так что всегда
показывает ваши клавиши, а не зашитые. Проблемы чтения файла и неверные
значения в `[reader]` сообщаются при старте, непонятные клавиши и
неизвестные действия в `[keys]` просто не учитываются — читалка в любом
случае продолжает работать.

Порядок старшинства: ключ командной строки, затем конфиг, затем то, что
читалка запомнила с прошлого запуска. Путь к другому файлу — `--config`.

## Читалка в браузере

На iPhone терминала нет, поэтому у fb2read есть вторая читалка — та же самая,
но в браузере. Она собрана из того же ядра: разбор, вёрстка, поиск и правила
закладок там общие с терминальной, а место в книге хранится номером абзаца, так
что книга, брошенная на ноутбуке, откроется на телефоне на том же месте.

Открыть: **<https://w2713.github.io/fb2read/app/>**

Что она умеет: открывать FB2 и EPUB с устройства, помнить место и закладки,
оглавление, поиск по книге, сноски с возвратом, четыре темы, разворот в две
колонки на широком экране. Книги **остаются в
браузере**: открыл один раз — дальше она в списке и открывается касанием, без
поисков файла. Приложение ставится на домашний экран и работает без сети —
книгу можно читать в самолёте. И умеет обмениваться с тем же сервером
синхронизации, что и терминальная: книга с ноутбука приезжает на телефон вместе
с местом и закладками.

### Разворот: две колонки на широком экране

За столом окно шире книги, и колонка в 34 рем оставляла по краям пустые поля.
Кнопка «Разворот» — или клавиша `v`, та же, что в терминале, — ставит книгу
разворотом из двух колонок во всю высоту окна. Выбор запоминается, как тема и
размер текста.

Разворот **листается**, а не прокручивается, и это не прихоть: многоколонник CSS
ведёт текст до низа первой колонки и продолжает в следующей — при прокрутке вниз
читателю пришлось бы возвращаться наверх за каждой второй колонкой. Листают
стрелками, `PageUp` и `PageDown`, пробелом или колесом мыши; `Home` и `End` —
в начало и в конец книги. Место, оглавление, поиск, закладки и сноски работают
как прежде: все они переходят к абзацу, а разворот лишь показывает ту страницу,
на которой тот лежит.

**На телефоне разворота нет**, и это решено нарочно. Порог — по двум измерениям
сразу: ширина от 51 рем и высота от 30. Одной ширины мало: iPhone в альбомной
ориентации даёт окно 844×390 и проходит по ширине с запасом, а колонка в нём
вышла бы в пять строк. Ниже порога кнопки нет вовсе, а запомненный выбор не
теряется: вернулись за стол — разворот снова на месте.

Ленивая вёрстка в развороте выключена, и это цена, а не упущение. Высоты абзацев
в ней угаданы, а из высот складывается число колонок, то есть вся длина книги:
измерено, книга росла под читателем с 326 576 до 358 976 пикселей, и место
уезжало ровно на разворот. Почём обходится честная вёрстка — книга в шесть тысяч
абзацев, окно 1440×900:

| | в развороте | при прокрутке |
|---|---|---|
| включить разворот | 363 мс | — |
| листнуть страницу | 2 мс | — |
| нажать «крупнее» | 437 мс | 22 мс |
| найти и подсветить | 224–389 мс | — |
| один шаг протяжки окна мышью | 21 мс | — |

Последняя строка — единственная, где пришлось схитрить. Честная перевёрстка
стоит 426 мс, а протяжка края окна выдаёт размеры десятками: окно тащилось
рывками по два с половиной кадра в секунду. Поэтому на время протяжки книге
возвращается ленивая вёрстка, а честная считается один раз — когда край
отпустили, и страница тогда же встаёт ровно на своё место.

Проверено в Chromium: тринадцать проверок листают стрелками и колесом, ходят по
оглавлению, ищут, меняют размер текста, тащат окно, закрывают книгу и сужают окно
до iPhone в альбомной. Как
многоколонник ведёт себя в Safari на iPad, отсюда не видно — стоит посмотреть
глазами.

Большие книги она верстает лениво: браузеру велено верстать только то, что
видно на экране. Разница на книге в три тысячи абзацев, при том что сама книга
в пятнадцать раз больше маленькой:

| | было | стало |
|---|---|---|
| нажатие «крупнее» | 200 мс | 67 мс |
| и во сколько раз дороже, чем на маленькой книге | втрое | во столько же |
| открытие — во сколько раз дороже маленькой | 4.6× | 2.6× |

На телефоне, где процессор вчетверо медленнее, это книга в шесть тысяч абзацев:
открытие 2835 → 1318 мс, нажатие «крупнее» 2262 → 213 мс.

Абзацы при этом никуда из страницы не деваются — браузер лишь не тратится на
вёрстку того, до чего читатель не дошёл. Поэтому и место в книге, и оглавление,
и закладки, и сноски работают ровно как прежде.

У ленивой вёрстки есть цена, и она неочевидна: высота ещё не свёрстанных
абзацев сперва угадана, а потом уточняется — и всё, что уточнилось выше места
чтения, уносит читателя. Измерено: прыжок на трёхтысячный абзац, и за две
секунды он уполз на 1245 пикселей. Chromium придерживает содержимое сам и
изъяна не показывает (снос 0.125 пикселя), а Safari — нет. Поэтому читалка
придерживает место сама, а браузерные проверки нарочно выключают придержку
Chromium, чтобы мерить то, что увидит iPhone.

Где что лежит: сами книги, места и закладки — в IndexedDB браузера, на вашем
устройстве. Наружу не уходит ничего, пока вы не настроите синхронизацию.

Синхронизация настраивается там же, на первом экране: адрес сервера и токен —
те же, что в конфиге терминальной читалки. Сервер при этом должен разрешить
браузеру к себе обращаться, иначе тот молча откажется:

```bash
FB2READ_SERVER_ORIGIN=https://w2713.github.io fb2read-server
```

Одно предупреждение, и его стоит знать: браузер вправе стереть хранилище сайта,
куда давно не заходили, — iPhone делает это примерно через неделю. Установка на
экран «Домой» этому мешает, поэтому читалка про неё и напоминает.

Собрать и посмотреть локально:

```bash
pnpm --filter @fb2read/web build
pnpm --filter @fb2read/web preview
```

Иконки нарисованы из `packages/web/public/icons/*.svg`; перерисовать их (нужен
установленный Playwright с Chromium) — `node scripts/make-icons.mjs`.

Читалка проверяется в настоящем Chromium: полсотни проверок открывают книги,
ищут, ставят закладки, ходят по сноскам, листают разворот, тащат окно,
перезагружают страницу и выключают сеть по-настоящему. Чего эти проверки не показывают — как всё ведёт
себя в Safari на iPhone: там свои правила и по хранилищу, и по запуску с
домашнего экрана. Это стоит посмотреть глазами, когда читалка окажется в сети.

## Перенос на TypeScript

Идёт перенос читалки на TypeScript, чтобы её можно было ставить и на
Windows, и на Android, и открывать книги на iPhone через браузер. План
целиком — в [docs/typescript-port-plan.md](docs/typescript-port-plan.md).

Перенос закончен. Сделано всё, что описано выше: ядро (разбор FB2 и EPUB,
починка битых файлов, вёрстка, поиск, состояние, конфиг, раскладка клавиш),
чтение в терминале без curses, список книг с возвратом к нему после чтения,
готовые сборки под все системы и установщики, синхронизация книг и позиции
через сервер, читалка для браузера с библиотекой, работой без сети и тем же
обменом с сервером.

```bash
pnpm install
pnpm build            # ядро и бандл CLI
pnpm test             # 474 теста
pnpm typecheck
node packages/cli/dist/fb2read.mjs книга.fb2
```

Интерфейс проверяется не глазами. Читалка не знает про терминал напрямую:
между ними небольшой слой, и в тестах вместо настоящего терминала стоит
эмулятор `@xterm/headless`. Тест посылает те же байты, что послал бы
терминал при нажатии клавиши или щелчке мыши, и читает получившийся экран
вместе с начертанием каждой ячейки — курсив, подчёркивание сноски,
подсветку найденного. Это работает внутри процесса, поэтому быстро и
одинаково на всех системах. Отдельно девять проверок поднимают настоящий
псевдотерминал: они ловят то, что иначе не проверить, — сырой режим,
сигнал об изменении размера окна, кириллицу при `LC_ALL=C` и возврат
терминала в чувство при выходе.

Каждый сценарий из `tests/test_ui.py` эталонной версии имеет соответствие
среди этих проверок.

`fb2read.py` остаётся в репозитории как эталон: по нему машинально
проверяется, что новая версия читает книги ровно так же. Удалить его стоит
не раньше, чем новая читалка поработает на настоящих книгах.

Сверка запускается одной командой:

```bash
./scripts/diff-dump.sh
```

Скрипт собирает восемь книг-образцов одним и тем же кодом (`cp1251`, zip,
битый файл, EPUB 3 с `nav`, EPUB 2 с NCX, книга с картинкой) и сверяет 57
проверок: полный разбор в JSON, `--info`, `--toc` и `--dump` при трёх
ширинах и двойном интервале. Отдельно проверяется, что позиция чтения и
закладки, записанные версией на Python, читаются новой реализацией с тем же
ключом книги — переход не теряет места в книгах.

## Разработка эталонной версии

```bash
pip install -e ".[test]"
pytest
```

Тесты делятся на две части. `tests/test_core.py` проверяет разбор, починку
битых файлов, перенос строк и хранение состояния обычными вызовами функций.
`tests/test_ui.py` запускает читалку целиком в псевдотерминале и читает
экран эмулятором `pyte` — так проверяются вещи, которые иначе видны только
глазами: разворот на две страницы, переход по сноске, начертание символов,
поведение при `LC_ALL=C` и при изменении размера окна.

Приёмы, важные для устойчивости этих тестов:

* размер окна выставляется до запуска программы, иначе первый кадр
  рисуется в другом размере и модель экрана расходится с реальностью;
* дочернему процессу отдаётся управляющий терминал, иначе ядро не шлёт
  `SIGWINCH` и ресайз не проверить;
* после нажатий посылается `Ctrl+L`: curses обновляет только изменившиеся
  ячейки, а полная перерисовка синхронизирует эмулятор с программой.

## Типографика

По умолчанию читалка верстает так же, как эталонная реализация на Python, —
байт в байт, и это сверяется в CI. Две вещи включаются по просьбе:

| | Клавиша | Ключ | Настройка |
|---|---|---|---|
| выключка по формату: ровный правый край | `J` | `--justify` | `justify = yes` |
| переносы слов по слогам | `H` | `--hyphens` | `hyphens = yes` |

Вместе они и задуманы: выключка без переносов в узкой колонке растягивает
промежутки заметно. На абзаце шириной 24 знака переносы убрали строку,
кончавшуюся одиннадцатью пустыми местами, — «девять десять» стало
«девять десять одиннад-».

Переносы расставляются правилами, без словаря: гласная в каждой части, одну
букву не отрывают, `ь`, `ъ` и `й` не начинают перенос, согласную не отрывают от
гласной за ней. Этого хватает, чтобы перенос был допустимым, но не всегда
словарным: рядом с верным «подъ-езд» правила предложат и «по-дъезд». Словарного
качества они не дают и не обещают.

## Чего пока нет

* ленивая вёрстка **в терминале**: книга раскладывается в строки целиком при
  открытии, поэтому очень большие файлы открываются не мгновенно. В браузере
  это сделано (см. ниже), в терминале — нет: там вёрстка занимает 258 мс из
  737 мс открытия книги в 5.8 МБ и повторно не считается, а плоский список
  строк держит на себе и листание, и процент в шапке, и переход к блоку, и
  разворот в две колонки. Что в терминале исправлено — протяжка окна мышью:
  раньше каждое знакоместо стоило отдельной перевёрстки (тридцать знакомест на
  большой книге — четыре секунды без ответа), теперь перевёрстка одна, когда
  окно отпустили.
